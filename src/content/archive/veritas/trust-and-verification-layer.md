## 1. Executive Summary

The Trust and Verification Layer is the heart of VERITAS. It takes the atomic claims generated by the Evidence Extraction Engine and rigorously proves or disproves them against the original source material. This article details the entailment logic and citation injection mechanics.

## 2. Problem Statement

Once a claim is isolated, the system must determine if the provided context supports the claim. Standard cosine similarity fails here. A source text might say "Revenue did *not* increase," and the claim might say "Revenue *did* increase." The cosine similarity between these two sentences is extremely high, but the semantic meaning is diametrically opposed.

## 3. Why Existing Solutions Were Not Enough

Standard vector database lookups return related text, but they do not perform logical entailment. They cannot answer the boolean question: "Does Document A prove Claim B?"

## 4. Design Goals

- **Boolean Entailment:** Definitively output `SUPPORTED`, `CONTRADICTED`, or `NEUTRAL` for every claim.
- **Traceability:** Return the exact snippet of text that drove the entailment decision.
- **Fail-Safe Mechanism:** If a claim cannot be supported, the system must redact it from the final output.

## 5. System Architecture

The Verification Layer operates as the final gatekeeper before the text is presented to the user.

Architecture Diagram: Atomic Claim -> Entailment LLM (cross-referencing Source Text) -> Boolean Result + Snippet -> Redaction/Citation Engine -> Final UI

## 6. Technology Stack

```text
Backend: Node.js (TypeScript)
Entailment Engine: OpenAI GPT-4o
```

## 7. Component Breakdown

1. **Entailment Evaluator:** A specialized prompt chain that acts as a strict judge, comparing a single claim against a specific source document.
2. **Citation Injector:** Maps successful verifications back to the original draft text and inserts markdown citations (e.g., `[1]`).
3. **Redaction Engine:** Removes or flags claims that return `CONTRADICTED` or `NEUTRAL`.

## 8. Data Flow

Sequence Diagram: `[Claim + Source Text]` -> Evaluator Agent -> `{"status": "SUPPORTED", "quote": "..."}` -> Citation Injector -> Final Formatted String

## 9. Design Decisions

- **Strict Judging Prompt:** We explicitly instruct the Entailment Evaluator to assume the claim is false unless the source text explicitly and undeniably proves it. This prevents the LLM from giving the draft the "benefit of the doubt."

## 10. Trade-offs

- **False Negatives vs. False Positives:** We tuned the system to tolerate a high rate of False Negatives (rejecting a claim that is actually true but poorly phrased) to completely eliminate False Positives (approving a hallucination).

## 11. Challenges Faced

Re-assembling the text. Once claims are verified and citations are generated, injecting those citations seamlessly back into the fluid paragraphs of the original draft without breaking the grammar or flow was a significant algorithmic challenge.

## 12. Engineering Lessons

- **String Matching is Fragile:** Attempting to use RegEx to find the exact location of a verified claim in the original draft is brittle. Instead, we pass the original paragraph and the verified citations to a final, lightweight "Formatting Agent" to seamlessly weave the citations into the prose.

## 13. Performance Considerations

Verifying 20 claims sequentially is too slow. We execute all entailment checks concurrently via `Promise.all`, constrained only by the API rate limit.

## 14. Security Considerations

- *Current Implementation:* The layer operates solely on text in memory.

## 15. Scalability

The stateless nature of the entailment evaluator allows for infinite horizontal scaling.

## 16. Future Roadmap

- **NLI Model Integration:** Replacing the GPT-4o entailment step with a dedicated Natural Language Inference (NLI) model (like DeBERTa) to reduce latency and costs for the verification step.

## 17. Conclusion

The Trust and Verification Layer ensures that VERITAS lives up to its name. By relying on strict logical entailment rather than simple semantic similarity, it provides enterprise-grade confidence in generative outputs.
